# Xiaomi Passport Auto-Refresh Design

Date: 2026-07-20
Status: Implemented and verified

## Objective

Allow Terra Server to renew the `i.mi.com` Xiaomi Notes session automatically when an upstream request returns HTTP 401 or 403. Passport refresh credentials are stored with Windows current-user DPAPI, can be updated from the local Settings page, and are never returned to the frontend.

## Evidence boundary

The 2026-07-20 HAR proves this sequence:

1. `GET https://i.mi.com/api/user/login` returns `data.loginUrl` on `account.xiaomi.com/pass/serviceLogin` with `sid=i.mi.com` and a callback targeting `https://i.mi.com/sts`.
2. The Passport JSON flow returns `ssecurity`, `nonce`, and a signed location.
3. `GET https://i.mi.com/sts` returns a redirect and sets `serviceToken`, `userId`, `i.mi.com_slh`, and `i.mi.com_ph`.
4. The issued serviceToken hash matches the token used by subsequent successful `/note/full/page` and `/note/note/{id}/` requests.

The implementation must discover the Passport URL dynamically and must not reuse the supplied tool's `sid=micoapi` profile.

## Credential storage

Store one versioned JSON bundle under the DPAPI secret name `xiaomiPassportRefreshCredentials`:

```json
{
  "version": 1,
  "passToken": "...",
  "userId": "...",
  "cUserId": "...",
  "deviceId": "..."
}
```

Environment variables may explicitly provide the four fields and take priority only when all four are valid. The Settings page cannot override an active environment bundle. Values are never included in client backup, Terra data backup, logs, audit records, API responses, URLs generated by Terra, or browser persistence.

## One-time import

A local CLI reads the labeled `myinfo.txt` format, validates all four values, stores the JSON bundle through DPAPI, rereads it to verify the round trip, and outputs only redacted completion status. Terra runtime never reads `myinfo.txt`.

## Passport refresh flow

1. Request the fixed `https://i.mi.com/api/user/login` endpoint with an HTTPS `followUp` on `i.mi.com`.
2. Validate the returned login URL: HTTPS, host `account.xiaomi.com`, path `/pass/serviceLogin`, `sid=i.mi.com`, and callback HTTPS host/path `i.mi.com/sts`.
3. Request the discovered login URL with `_json=true` and a Cookie containing passToken, userId, cUserId, and deviceId.
4. Parse the prefixed JSON response and require `ssecurity`, `nonce`, and `location`.
5. Validate the signed location as HTTPS `i.mi.com/sts` with `sid=i.mi.com`.
6. Add `clientSign = base64(sha1("nonce=<nonce>&<ssecurity>"))` and request with redirects disabled.
7. Require Set-Cookie values for serviceToken, userId, `i.mi.com_slh`, and `i.mi.com_ph`.
8. Merge them into the existing complete Cookie while preserving unrelated Cookie pairs. If no Cookie exists yet, create one with the issued fields plus safe `i.mi.com` locale/trusted-device defaults.
9. Persist the refreshed or newly created complete Cookie to DPAPI, invalidate the secret cache, and hot-reload the connector.

All requests use strict timeouts, response-size limits, fixed/trusted hosts, manual redirect handling, generic errors, and no body/header logging.

## Automatic retry

- The first 401/403 from a Xiaomi Notes request triggers a shared single-flight refresh when refresh credentials are configured.
- Concurrent failed requests await the same refresh promise.
- After refresh, each original business request may retry once.
- A second authentication failure marks credentials invalid.
- Refresh failures do not recursively retry and do not count as ordinary transient upstream failures.
- Non-authentication failures retain the existing circuit-breaker behavior.

## Settings API and UI

Status adds only redacted metadata: configured, source, writable, refreshing, last success, last failure, and message.

Loopback-only endpoints:

- `PATCH /api/xiaomi-notes/refresh-credentials` merges non-empty submitted fields into the stored bundle. Initial setup requires all fields.
- `POST /api/xiaomi-notes/refresh-now` obtains an initial Cookie when none exists, or refreshes the current DPAPI Cookie, and returns redacted connector status.

The Settings form never receives stored values. Blank fields mean unchanged. Its primary action saves the Passport bundle and immediately obtains the Cookie; a secondary action saves without network validation. Inputs are cleared after the bundle is saved even if the subsequent validation request fails. passToken uses a password field with an explicit temporary visibility toggle.

## Verification

Tests cover parsing, host/path/query trust boundaries, clientSign, Set-Cookie extraction, initial Cookie creation, Cookie merge, single-flight behavior, one retry only, refresh failure boundaries, DPAPI ciphertext, one-time import, environment priority, local-only API access, redacted status, and all existing Xiaomi smoke suites.
